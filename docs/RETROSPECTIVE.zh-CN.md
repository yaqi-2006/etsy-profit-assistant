## 3. 为什么没有商业化

四条结构性理由，每一条都与代码质量无关。

### 3.1 功能已被免费工具覆盖

产品列出的七项「差异化」——成本复用、数字可解释、来源可追溯、本地不上传、逐单贡献、Offsite Ads 情景、报告导出——在 2026 年 10 月**没有一项是独有**：

| 竞品 | 覆盖内容 | 价格 |
| --- | --- | --- |
| [Seller Profit Guard](https://sellerprofitguard.com/tools/profit-guard) | 功能高度重叠：浏览器本地解析、订单级贡献、SKU 成本库、缺成本告警、Offsite Ads 12%/15% 情景、审计留痕、报告导出、6 种语言 | 免费（页面明示不会收费） |
| [F5 Design Studio · Etsy Statement Decoder](https://f5design.studio/tools/etsy-statement-decoder) | 原生月结单导入：无服务器无账号、分离买家付的税与真实费用、多月 take rate | 免费 |
| [StitchProfit](https://stitchprofit.com/) | 上传 Etsy CSV、浏览器本地、无订阅 | $19 一次性 |
| [Ardent Workshop](https://www.ardentworkshop.com/products/etsy-financial-tool-excel/) | 粘贴月结单 → 收入/费用/净额按月汇总 | $10.95 一次性 |

> 上表价格为 2026-10-16 查阅各官网所得，此后可能变动；「覆盖内容」是对公开产品页的描述性归纳，不是购买或安装后的功能验收。同类的免费工具还有 LedgerOS、useSolveKit、tryprimeconnect、peakappsstudio，以及若干「免费工具 + 指南内容」的站点。

### 3.2 渠道是制度性关闭的，不是没找到

| 渠道 | 状态 |
| --- | --- |
| r/EtsySellers（24.6 万成员） | 规则标题原文即 **"No Promotion, and No Feedback/Research for Seller Tools"**——连「请大家帮我测个工具」都禁止 |
| r/Etsy | 禁止 seller tools「**whether directly linked or not**」 |
| Etsy 官方社区 | 社区政策第 8 条禁止一切推广内容；Etsy Teams 推广帖 2025-09 已取消 |
| Chrome Web Store | **2021-02-01 起无原生支付**，扩展内收款必须自建 |

对一个零受众的开发者，唯一不违规且可复利的渠道是**长尾 SEO 内容站**——而那个词簇已经被上述 8 个以上站点占据，周期以季度计。

### 3.3 愿意付钱的那部分需求，已经被别人承接

| 需求 | 承接方 | 价格 |
| --- | --- | --- |
| 逐单利润 + COGS + Ads 同步 | ProfitTree | $5.99–29.99/月 |
| 配方级 COGS（BOM/批次） | Craftybase / Stocksmith | $49/月起 |
| 原生记账 | Seller Ledger | $10/月起 |
| SEO / 选品 | eRank / EverBee / Alura | $5.99–69/月 |

免费侧被免费 CSV 工具锚定，付费侧被上述产品占满，中间没有位置。

### 3.4 无后端 = 无复利，而唯一还有付费空间的需求全都需要后端

真正未被满足的四项——跨月历史与趋势、免手工下载的自动化、可交给 CPA 的合规产出、多店协作——**全部需要持久化或平台授权**。这直接推翻本项目「纯客户端、无后端」的前提。

**要收钱，就必须放弃这个架构。** 这不是「以后加个后端」的优化项，是商业天花板。

### 3.5 平台方既是裁判也是潜在选手

- Etsy 自 2024 年起持续收紧第三方数据访问，2025-07-14 起 Orders CSV 导出延迟 2 周。
- 2025-07 Etsy 向卖家发问卷，直接询问对「Accounting, bookkeeping and finance management」的兴趣。
- 2026-09 新版 Payment account 已开始把订单收入与相关费用**分组展示**——即 Etsy 自己在解决「逐单费用看不懂」。

### 3.6 顺带一提：收款不是瓶颈，但计划里选错了通道

计划按 Lemon Squeezy（5% + $0.50）测算。实际核验：

- **Stripe** ✘ 官方写明 "not intended for users in mainland China"
- **Lemon Squeezy** ✘ 银行提现名单无中国大陆，且已被 Stripe 收购
- ✅ **Creem** 官方支持中国、个人 → 支付宝，3.9% + $0.40
- △ **Paddle** 个人可注册、5% + $0.50，能否电汇到大陆银行官方未说明

收款能解决，但它从来不是这个项目的主要风险。

## 4. 根因：跳过的是第 0 步

计划第 12.2 节「现在先做的五件事」**全部是联系真实卖家做需求验证**。实际发生的是：

- 计划的验证路径依赖 Reddit 等卖家社区，而 Reddit 与 Google 直连超时（`ERR_CONNECTION_TIMED_OUT`），代理没能走通。
- 逐一核对候选渠道后，没有找到同时满足「社区规则允许开发者征集反馈」与「可由本人远程参与」的入口。
- 需求验证因此被跳过，直接转入开发。此后 3.5 小时做出完整产品，**但没有任何一位真实卖家看过**。

**所以死因不是执行力，是在第 0 步放弃了验证。** 而这个放弃在当时是理性的——渠道确实走不通。问题在于：渠道走不通本身就是最重要的商业信号，它被当成了「换个方法继续做」的障碍，而不是「这个市场你进不去」的答案。

连锁反应很清楚：没有用户 → 拿不到真实月结单 → 核心假设永远无法验证 → 无法对外声称「能用」→ 更难获得用户。

## 5. 如果重来，什么会不同

按成本从低到高：

1. **先花 2 小时确认「有没有一个允许推广的渠道」**，而不是先写代码。没有渠道 = 没有生意，这一条可以极便宜地提前知道。
2. **先拿 3–5 份真实月结单**。这是唯一没验证的假设，也是最便宜的证伪点。当时以为「必须等用户才能拿到文件」，实际上完全可以在卖家社区之外（例如公开分享的脱敏样例、会计从业者）先解决。
3. **先让 3–5 位卖家说出他们现在的做法**。不需要访谈十个人，三个就够判断「现有的免费表格是否已经够用」。
4. **在写第一行代码前，先问「这件事免费工具做了吗」**。当时已经查过竞品（计划 §2.2 列了 Seller Ledger、EverBee、Alura、StitchProfit），但查的是「有没有人商业化」，没查「有没有人免费做了」——后者才是决定性的。

## 6. 仍然可复用的资产

即使不作为产品，这些东西是有价值的：

- **财务核心的分值纪律**：整数分 + BigInt 累加、未知 ≠ 零、原子导入、同 ID 冲突整批拒绝、拒绝靠日期金额猜订单关联。这套处理方式可以直接搬到任何「平台流水 + 自有成本」的场景。
- **原生格式的语义处理**：识别出「月结单 `Net` 已含行内费用与税，不能再扣一次」是这类工具最常见的错误来源，这一条判断是对的。
- **严格打包白名单**：`build-extension.cjs` 按精确清单打包、缺失即失败、不做递归遍历。
- **诚实的文档体系**：111 项本地检查逐项记录、哈希可追溯、明确写「未验证真实导出」「不是税务报告」「与 Etsy 无关联」。同类项目里很少见。
- **一份商业计划的可执行范例**：上面那份 69 KB 的计划在方法上是扎实的（证据分级、单位经济、止损条件都写了），它失败的地方不是分析质量，而是**分析出来的门槛没有被当作门槛**。
